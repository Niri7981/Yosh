# Yosh v0.1.1-rc.4 — explicit legacy Pay Dev Mainnet signer

Version 0.1.1, candidate rc.4, native build 5. Frozen rc.3 is the predecessor.
This candidate does not overwrite rc.3 or formal Yosh. Bundle/data namespace
is com.yosh.pay-development.v011rc4 / Yosh Pay Dev v0.1.1-rc.4; ports are
13349/13350/13351. All economic state remains candidate-local. Pay and pay-kit
sources are unchanged. No payment is authorized by this release.

Default Mainnet lookup uses the candidate's isolated Keychain service.
Only an operator-owned root `mainnet-signer-acceptance.json` (regular file,
current owner, 0600, bounded size, no symlink) with exactly
`{"version":1,"identity":"legacy-pay-dev-mainnet"}` selects the fixed historical
Pay Dev Mainnet slot. This is accepted only by the rc.4 build in validated
Dev Mainnet mode. No HTTP/MCP field or environment service string selects it.
Offline and library slots remain isolated, production lookup is unchanged.

The legacy slot is read-only: provisioning is rejected, absence has no fallback,
and loaded Mainnet signers must match public address
5jgN7QN4uYdYLHrEcUvZczciV144TRxz2Xjr1MYPJYHj. Identity metadata must continue to
match the ledger; this is not a key migration or a ledger import. Do not change
selection while a runtime or purchase is active. Normal signing remains within
the existing backend wallet interface; tools must never extract secret data.

Readiness in this task is metadata/public-chain only. Existing wallet inventory
APIs derive public keys by reading the private Keychain value, so they are not
invoked under the user's no-secret-read constraint. A matching historical public
identity plus current item existence is not a fresh cryptographic signer proof.
No funded acceptance, Grant creation, Budget change, or Mainnet enablement is
included. Build provenance records fresh checks and artifact fingerprints.

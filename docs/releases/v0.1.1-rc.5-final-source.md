## Historical freeze and final identity

`integration/release-candidate/source-lock.json` records the initial rc.5 build.
It predates the validated consent v3, retry/recovery, lease and controller repairs.
At final review, twelve code/test files differed from that record and four new
controller source/test/review files were absent. Installed repair overlays tracked
those later changes, but the original source lock alone could not prove the final
source. Historical release notes retain their original scope and limitations.

The active build entry now uses `final-source-lock.json` (schema 3,
`recordKind: final-rc5-source`). The historical lock and rc.1–rc.4 records remain
unchanged. The final record hash-binds the historical rc.5 lock, reviewed baseline,
rc.4 predecessor and the complete Yosh/Pay file inventories. Each inventory binds
file membership, SHA-256 contents, symlink targets and Git executable modes.
Only the active final manifest excludes itself to avoid self-reference; it is
committed and copied alongside the source archives.

The inventory uses a verified fixed ancestor plus full source content, rather
than the current dirty flag or a tracked-only patch. Its identity therefore
survives staging and the archival commit while still rejecting source additions,
removals, mutations, mode changes and historical-lock changes. `RC5_FILES` remains
an explicit scope allowlist, including the final controller diagnostics, contract
and live-preflight regression sources and this release record. Freeze protection
and `verify_sources()` remain enabled.

Final source coverage includes stable economic-intent consent v3; explicit safe
pre-execution retries; post-Allow/pre-payment recovery; execution lease ownership
and fencing; bounded controller diagnostics; plan/execute/recover wiring; the
controller-specific 128 KiB `/pay/execute` body allowance; atomic Purchase,
reservation and Grant handling; original-payment recovery boundaries; and the
controlled Mainnet execution regressions. This archival step changes only release
engineering and documentation; the reviewed payment implementation stays frozen.

## Upstream Pay source and portable private overlay

Public Pay remains pinned to [#530 commit 402f67c44dd8d41d7d1584fcb5d868006ce8c891](https://github.com/solana-foundation/pay/commit/402f67c44dd8d41d7d1584fcb5d868006ce8c891),
with #514 commit `898135e5404018e61daa2644f30952507947e990` in its ancestry.
All tracked upstream files must match that commit. Neither public contract is
changed by this archive.

`integration/release-candidate/pay-overlay/` contains byte-identical source copies
of the existing private custody executable and public quote fixture. To prepare
a new sibling Pay checkout at the pinned commit, copy:

| Archived source | Destination in the sibling Pay checkout |
| --- | --- |
| `pay-overlay/yosh-controlled-mcp.rs` | `rust/crates/mcp/src/bin/yosh-controlled-mcp.rs` |
| `pay-overlay/agent402-mainnet-quote.json` | `rust/crates/mcp/tests/fixtures/agent402-mainnet-quote.json` |

These are build/test source inputs, not live execution output. The quote fixture
contains no payment signature, consent value or financial state. Verification
requires exact equality with the archived copies and rejects other upstream
source overlays. Dependencies remain pinned by the existing npm/Cargo locks and
reviewed pay-kit revision; offline build prerequisites remain explicit.

From the Yosh checkout with that sibling prepared:

```sh
python3 -B scripts/build-release-candidate.py check --pay ../pay
python3 -B scripts/build-release-candidate.py archive --pay ../pay \
  --output build.noindex/final-rc5-sources
```

The archive action writes Yosh and Pay source tarballs plus the final manifest.
It verifies every archive member against the complete inventory, rejects extra,
missing, duplicate, changed or unsupported members, and rechecks the live source.
It performs no payment, installation or build. Generated archives remain local;
Git contains the reconstructible source, locks and portable overlay inputs.

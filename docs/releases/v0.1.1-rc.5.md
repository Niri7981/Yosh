# Yosh 0.1.1-rc.5 — build 6

Uses upstream Pay #530 commit 402f67c44dd8d41d7d1584fcb5d868006ce8c891, including #514 commit 898135e5404018e61daa2644f30952507947e990. Pay implementation is unchanged; the private custody executable translates the public SpendRequest/ControlledRequest and unsigned lifetime interfaces.

Removed the temporary retryable boolean, UnavailableNotStarted variant, and custom replay-guard implementation. Only AuthorityDecision::RejectBeforeExecution permits exact-request retry with a new attempt. Deny, unavailable, timeout, cancellation, lost reply and every post-Allow outcome remain fenced. Pay permanently retains the original request fingerprint within its process.

Yosh returns that decision only for a synchronous missing or mismatched/expired one-time Mainnet acceptance check before invoking any purchase path, after confirming no owned Purchase or prior durable authority claim exists. Malformed receipts, IO failures other than missing receipt, ledger errors and ambiguous outcomes never receive it. Full challenge binding is verified at ControlledRequest plan, before Purchase/reserve or unsigned construction. No challenge is reconstructed from the selected offer.

Because the public SpendRequest intentionally omits the full envelope, successful pre-authority consent creates a durable, atomic caller/operation/request/quote/attempt fence before Allow (migration 020_external_authority_claim). Controller plan then validates the source envelope and uses the existing atomic Purchase/reserve/permit path. An interrupted Allow before plan remains fenced after restart; it cannot become a fresh payment. Existing Purchase recovery preserves original evidence, signature, accounting and delivery.

Controlled delivery uses the upstream inclusive 64 MiB body limit. The private JSON bridge permits byte-array expansion. Existing declared Resource delivery limits are still enforced before paid egress; no 64 KiB post-payment rejection remains. The compatibility unsigned preflight uses the pinned SDK, including its blockhash and mint-decimals RPC validation. Only disposable tests permit loopback fixture RPC.

Product 0.1.1 / candidate rc.5 / build 6. Independent bundle com.yosh.pay-development.v011rc5, ports 13449–13451 and Application Support directory. No key copy, migration, export, Mainnet payment, commit or push. Grant, Daily Authority, consent, signer and transaction recovery checks are preserved.

The exact upstream implementation does not emit the former Yosh-private eight-stage tracing stream. Missing instrumentation remains complete=false with no invented events; custody provenance, persisted original evidence and actual Codex/Pay integration tests remain available. The Offline RPC simulator now implements the SDK isBlockhashValid check against its persisted fixture blockhash set.
